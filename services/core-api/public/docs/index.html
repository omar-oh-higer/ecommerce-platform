Introduction

REST API of the core application (Laravel). Damascus University — Internet Applications project 2026.

Base URL: http://localhost:8000 
Every endpoint is served under `/api/v1` and returns JSON. Always send `Accept: application/json`.

**Errors** always have the same shape:

```json
{"error": {"code": "VALIDATION_FAILED", "message": "The given data was invalid.", "details": {}}}
```

Rely on `error.code` (stable), not on `message`. Main codes: `UNAUTHENTICATED` / `INVALID_TOKEN` (401),
`FORBIDDEN` (403), `NOT_FOUND` (404), `INSUFFICIENT_STOCK` / `INVALID_STATUS_TRANSITION` (409),
`VALIDATION_FAILED` (422), `TOO_MANY_REQUESTS` (429), `INVENTORY_UNAVAILABLE` (503).

**Lists** are paginated: `data`, `links` (`next` is `null` on the last page) and `meta` (`current_page`, `last_page`, `per_page`, `total`).

<aside>Ready-made accounts after setup: admin <code>admin@store.test</code> / <code>Admin@12345</code>,
customer <code>customer@store.test</code> / <code>password</code>.
Use <b>Try it out</b> on <code>POST /auth/login</code>, copy <code>access_token</code>, then paste it in the auth field of any protected endpoint.</aside>

Authenticating requests

To authenticate requests, include an Authorization header with the value "Bearer {YOUR_JWT_TOKEN}".

All authenticated endpoints are marked with a requires authentication badge in the documentation below.

Get a JWT from POST /api/v1/auth/login (field access_token) and send it as Authorization: Bearer {token}. Tokens expire after 60 minutes; use POST /api/v1/auth/refresh.

Authentication

JWT authentication. Send the token as Authorization: Bearer {token}.

Register

Creates a customer account and logs it in. Sending role has no effect. Limited to 10 registrations per minute per IP.

Example request:
curl --request POST \
    "http://localhost:8000/api/v1/auth/register" \
    --header "Content-Type: application/json" \
    --header "Accept: application/json" \
    --data "{
    \"name\": \"Omar\",
    \"email\": \"omar@example.com\",
    \"password\": \"Secret123\",
    \"password_confirmation\": \"Secret123\"
}"

Example response (201, Registered):


{
    "access_token": "eyJ0eXAiOiJKV1QiLCJhbGciOiJIUzI1NiJ9...",
    "token_type": "bearer",
    "expires_in": 3600,
    "user": {
        "id": 3,
        "name": "Omar",
        "email": "omar@example.com",
        "role": "customer",
        "created_at": "2026-11-04T10:15:00+00:00"
    }
}

Example response (422, Email taken / weak password):


{
    "error": {
        "code": "VALIDATION_FAILED",
        "message": "The given data was invalid.",
        "details": {
            "email": [
                "The email has already been taken."

            "password": [
                "The password field must be at least 8 characters."

Orders

Place an order

requires authentication

One call to the inventory service reserves every item (all or nothing). Prices always come from the database: any price sent by the client is ignored. If saving the order fails after the reservation, the stock is given back. Limited to 10 orders per minute per user.

Example request:
curl --request POST \
    "http://localhost:8000/api/v1/orders" \
    --header "Authorization: Bearer {YOUR_JWT_TOKEN}" \
    --header "Content-Type: application/json" \
    --header "Accept: application/json" \
    --data "{
    \"items\": [
        {
            \"product_id\": 6,
            \"quantity\": 2
        }
    ]
}"

Example response (201):


{
    "data": {
        "id": 1,
        "status": "pending",
        "total": "53.50",

Change order status

requires authentication

Admin only (a customer gets 403, even on their own order). Allowed: pending → confirmed | cancelled, confirmed → shipped | cancelled, shipped → delivered. Cancelling gives the stock back to the inventory service. The customer is notified. Cancelling always succeeds, even when the inventory service is down: the response then has stock_return: "pending" and a background job returns the stock as soon as the service is back (stock_return becomes "done").

curl --request PATCH \
    "http://localhost:8000/api/v1/orders/1/status" \
    --header "Authorization: Bearer {YOUR_JWT_TOKEN}" \
    --header "Content-Type: application/json" \
    --header "Accept: application/json" \

    \"status\": \"confirmed\"
